# Where marg stands, and what it would take to become a sandbox (review, 2026-11-20)

Written for the project owner after a full read of the repo, a run of the CLI and a live
session in the web viewer. It compares what is built with what you asked for on 2026-11-20:

> make roads freely; random road generators with curves, potholes and street shops; police,
> speed cameras and other things that make people obey; change traffic volume, the share of
> each vehicle class and each class's selfishness easily from the web UI; single-lane roads.

## 1. What exists today, in plain terms

**Size.** About 38,000 lines of Rust in 7 crates, a Python research API, a React web viewer,
a 520-entry parameter register, 20 ADRs, 17 shipped scenarios and phase reports P2–P8.
8 of 13 roadmap phases (P0–P8) are done. It builds and runs: `side_friction_street`
(30 simulated minutes, ~1.4 M agent-steps) takes 1.6 s on this VM.

**What it is built for.** A research instrument: every number traces to the Delhi parameter
guide, every run is reproducible bit for bit, experiments run as twin arms with common random
numbers, outputs are Parquet. That rigour is real and worth keeping. But it was built
*researcher-first*, and almost every point in your list is a *sandbox-first* feature. Both can
live together; today only the first exists.

| Area | Built | How you use it today |
| --- | --- | --- |
| Roads | "Ribbons": a polyline centre line with a width profile; lane-free (vehicles take any lateral position). Junctions (box, signal, priority, roundabout, median opening, splits), undivided two-way roads, footpaths, wrong-way paths | Write YAML by hand (`scenarios/*.yaml`) |
| Road features | Potholes (fields), waterlogging, humps, gradients, kerbside parking, bus stops, mid-block pedestrian crossings, obstacles, "attractors" (a stretch where autos/e-rickshaws stop more, e.g. a metro exit) | YAML; in the live view, "Add object" places a plain obstacle from four unlabelled number boxes |
| Vehicles | 15 types in 7 classes, each with drawn parameters (speed, gaps, accel, size) | Composition per entry, in YAML |
| Drivers | 7 traits per driver (aggressiveness κ, time pressure, risk tolerance, conformity, …), 10 personas, within-trip mood | κ population mean and a few links are live sliders (under raw names) |
| Violations | 11 types (red-light running, early start, amber go, box blocking, seepage, wrong way, footpath riding, opposite-side encroachment, late merge, forced entry, stop-anywhere) on one logged decision rule | **Off by default**: their coefficients are unset in the register, so nothing happens until you supply numbers |
| Enforcement | Signals can be in "police" control state (an officer runs the junction). The decision rule has an `enforcement` term | That term is **hard-wired to 0**. Police posts, cameras, halos: register entries exist (mostly unset), no code (planned P9.2) |
| Web viewer | Live sessions (play, step, speed, breakpoints, click a vehicle to inspect it), replay with SQL filtering, twin comparison, KPIs, time–space plot | Pick one of the 17 scenarios from a dropdown. The parameter panel lists 520 register paths (109 editable) such as `following.comfortable_decel.auto_rickshaw` |

## 2. Your wishes against what exists

| You want | Status | Gap |
| --- | --- | --- |
| Make a road freely | **Missing** (YAML only) | A web editor: planned as P12.1, after zones (P9), calibration on real data (P10) and city-scale networks (P11) |
| Random road generator | **Missing** | Nothing generates scenarios |
| Curves | **Partial** | Polylines can bend, but curvature only slows vehicles on turning paths *inside junctions*. On an ordinary curved road nobody slows for the bend |
| Potholes | **Built** | Need 14 numbers per scenario because the guide gives none (see §3) |
| Shops on the street | **Partial** | "Attractors" raise stopping rates; kerbside parking and pedestrians exist. There is no "shop" object that bundles them (stops + parking churn + pedestrians), and nothing draws them |
| Traffic police | **Partial** | Only as a junction control state. No police post that changes behaviour around it |
| Speed cameras | **Missing** | There are no speed limits and no speeding behaviour, so a camera has nothing to act on. This needs a new mechanism (an ADR, per the project rules) |
| Change traffic volume live | **Missing** | Demand is fixed when a session starts; changing it means editing YAML and restarting |
| Change class shares live | **Missing** | Same |
| Per-class selfishness | **Partial** | κ has one population mean (live) and per-persona shifts; no per-class shift. Per-class violation intercepts exist but are unset |
| Single-lane roads | **Partial** | A narrow ribbon (~3–3.5 m) behaves like one lane for cars, but two-wheelers still squeeze past, and nothing forbids overtaking. There is no lane-discipline mode |
| Easy, intuitive parameters | **Missing** | The panel is the raw register. No grouping by intent, no plain-language controls |

## 3. Things you should know before building on it

1. **The "unset" rule fights a sandbox.** 112 register entries are deliberately empty because
   the guide gives no number, and a mechanism that needs one refuses to run. `side_friction_street`
   carries 28 hand-set overrides just to turn potholes, parking, bus stops and pedestrians on.
   A road editor or generator is unusable unless there is a clearly labelled set of placeholder
   values. That is a decision for you (question 2 below), because it touches rule 1 of
   `CLAUDE.md` ("no magic numbers").
2. **Junctions lock up at moderate flows.** A signalised crossing with right turns can gridlock
   at 400–700 veh/h per arm (12 of 40 seeds at 700 stall). Roundabouts lock above light flows.
   A volume slider will hit this straight away, and much of that gridlock is a model artefact,
   not Delhi.
3. **Nothing is calibrated.** Values are literature values; several validation checks are
   missed and reported (not tuned). Fine for a sandbox, but outputs are not evidence yet.
4. **Speed** is ~900 ns per agent-step on this VM against a 555 ns budget. Fine for one live
   corridor; it matters for many-junction or generated networks.
5. **Small UI rot**: the header says "viewer protocol 1" (it is 4); KPI tiles still say
   "violations not modelled before P8" and "personas arrive in P8".

## 4. Proposed plan: a sandbox track ahead of P9–P12

Each item is sized for one session, with tests, in the order I would do them. Items marked ⚑
are modelling choices, so per the project rules they start as an ADR draft for your decision.

| # | Item | What you get | Size |
| --- | --- | --- | --- |
| S1 | **Live demand controls** | In the live view: a flow slider per entry (and one for all entries), and class-mix sliders. Logged as session commands, so a saved session still replays bit for bit | M |
| S2 | **Behaviour panel** | Plain-language sliders on top of the register: selfishness (κ) per class, patience, rule-following, phone use; a "violations on" switch; the raw register stays behind an "advanced" tab. Needs new register entries `traits.aggressiveness.shift.<class>` | M |
| S3 | **Sandbox defaults** (needs question 2) | A named preset filling the unset entries with labelled placeholder values, so every feature works out of the box. Runs using it are stamped `sandbox`, and the validation reports refuse them | S |
| S4 | **Enforcement** (P9.2 pulled forward) | Police posts and cameras as map objects with distance halos that feed the decision rule's enforcement term; a live toggle; violations drop near a post | M |
| S5 ⚑ | **Speed limits, speeding, speed cameras** | Posted limits on ribbons, a per-driver speeding choice, cameras that reduce it near them | M, ADR first |
| S6 ⚑ | **Curve speed on every road** | Vehicles slow for bends by local radius, reusing the junction rule `v = √(a_lat · R)` | S, short ADR |
| S7 ⚑ | **Single-lane roads** | Depends on what you mean (question 3) | S–M, ADR first |
| S8 | **Random road generator** | `marg generate --seed N --length 2km --curviness … --potholes … --shops … --junctions …` writes a valid scenario; a "Random road" button in the viewer. Same seed, same road | M |
| S9 | **Shop object** | A "shop" that bundles an attractor, parking churn and pedestrians in one placeable thing, drawn on the map | S |
| S10 | **Road editor** (P12.1, scoped down) | Draw a road on the map, set its width, drop potholes/shops/bus stops/humps/police/cameras, save as a scenario and run it, all in the browser. Junction editing comes later | L |

Not in the track: real-data calibration (P10) and city-scale networks (P11). The two known
junction problems (§3.2) should be fixed before or alongside S1, otherwise the volume slider
mostly shows gridlock.

## 5. Questions for you

1. **Order.** Is the S1–S10 order right? My suggestion: S1 + S2 + S3 first (you can play with
   volume, mix and selfishness on the existing roads within a few sessions), then S4–S7, then
   S8–S10.
2. **Placeholder values.** May the project carry a `sandbox` preset of made-up but plausible
   values for the 112 unset entries, clearly marked and excluded from validation? Or must every
   number still be sourced before a mechanism can run?
3. **Single lane.** Which do you mean?
   - (a) just a narrow road: physics decides who fits; two-wheelers may still squeeze past;
   - (b) a lane-disciplined road: no overtaking within the road, single file;
   - (c) a two-lane undivided road where overtaking means using the oncoming side (partly
     exists as opposite-side encroachment);
   - or a switch between them per road.
4. **Selfishness.** Is aggressiveness κ what you mean? It already drives smaller clearances,
   shorter gaps, harder acceleration and more violations. Or do you mean something narrower,
   such as not yielding?
5. **Speed cameras.** Should speeding be a violation like the others (a logged decision with
   a fine/detection term), or just a lower desired speed near the camera?

### Your answers (2026-11-20)

1. **Order:** yes. S1 + S2 + S3 first.
2. **Placeholder values:** allowed. They can be made up, reasoned out or tested; they need
   not be sourced. (S3 marks them as `sandbox` so they never pass as guide values.)
3. **Single lane:** all of (a), (b) and (c) as a per-road choice, plus a two-lane road
   whose kerb lane is mostly taken by shops and pedestrians (S7, with S9).
4. **Selfishness** is aggressiveness κ.
5. **Speed cameras:** still open; needed before S5.
